CURRICULUM.md §9「第1段階：半日コースの土台」を実機で確認するためのスケッチ集です。

**このボードはシリアルモニタが使えない**ので、結果はすべて **基板のLED（D2・オレンジ）** と
**手に持つテストLED** で読み取れるように作ってあります。

**ピンとして出ていないもの**

- `PD7` … RESET（ボタン。GPIO ではない）
- `PD3` / `PD4` … USB の D+ / D−（**A4・A7 は存在しない**）
- 番号 **13・14・17 は欠番**

> ⚠ 以前ここに載せていた表は `variant_CH32V003F4.h` からの**推測で、誤りがありました**
> （0・1・6 を「存在しない」、17 を「使える」、A4・A7 を「使える」としていた）。**公式図が正**です。

その他：

- **ボードの動作電圧は既定 5V**（公式ページ「3.3Vまたは5V(初期値)から選択可能」）。
  電圧選択ジャンプパッドで 3.3V にも変えられるが、**3V3ピン・5Vピンの出力は選択と無関係**
  → **ADC の基準電圧も 5V**。アナログ値を電圧に直すときは `v * 5.0 / 1024`
  → 330Ω の LED は 5V で 9.1mA。CH32V003 の推奨 8mA にほぼ収まる（抵抗値の選択は妥当）
  → HC-SR04 の TRIG も 5V ロジックで駆動できていた（レベル不足の心配は無かった）
- `analogRead` は **10bit（0〜1023）**
- `analogWrite` は **12bit（0〜4095）・PWM 1000Hz** ⚠ Arduino標準（0〜255）と違う
  → `setup()` に **`analogWriteResolution(8);`** を入れると 0〜255 で書ける
- **`LED_BUILTIN` は未定義** → `const int LED = 2;` と自分で書く
- `tone` `noTone` `pulseIn` `map` `millis` `micros` `random` `shiftOut`
  `analogReadResolution` `analogWriteResolution` `analogWriteFrequency` は**すべてコアに実装済み**
- 同梱ライブラリは `Adafruit_TinyUSB_Arduino` `EEPROM` `SPI` `USBPD_SINK` `Wire` の5つ。
  **`Servo` は入っていない**

## 書き込み手順（毎回これ）

1. USBを抜く
2. **RESETを押しながら** USBを挿す → すぐRESETを離す（青いPWR LEDが点灯）
3. Arduino IDE で「→（書き込み）」
4. `Image written.` が出たら **RESETを1回押す**

> ⚠ 書き込みに失敗するときは、USBハブを介さずPCへ直挿し／短いケーブルに変える／
> RESETを離すタイミングを変える、を試す。**失敗したパターンも記録**しておくと `x2_trouble` の材料になります。

## v02 / v04 の「番号の知らせ方」

v02・v04 は候補ピンを順番に1本ずつ試します。いま何番目を試しているかは、基板のオレンジLEDが教えます。

```
　■■■■■■　　　　　… 長く1回点灯（＝これから番号を知らせるよ）
　■　■　■　　　　　… 短い点滅の回数 ＝ 下の表の「順番」
　（そのあと対象ピンが2.5秒間ON／2秒かけてフェード）
```

**v02・v03（digitalWrite / INPUT_PULLUP・13本）**

| 順番 | ピン | 順番 | ピン | 順番 | ピン | 順番 | ピン |
|---|---|---|---|---|---|---|---|
| 1 | 0 | 5 | 5 | 9 | 9 | 13 | 16 |
| 2 | 1 | 6 | 6 | 10 | 10 | | |
| 3 | 3 | 7 | 7 | 11 | 12 | | |
| 4 | 4 | 8 | 8 | 12 | 15 | | |

**v04（PWM・6本）**

| 順番 | ピン | ねらい |
|---|---|---|
| 1 | 5 | 公式図で PWM 表示あり（◎のはず） |
| 2 | 6 | 同上 |
| 3 | 12 | 同上 |
| 4 | 1 | **焦点**：公式図に PWM 表示なし・コアには相補出力として存在 |
| 5 | 10 | **焦点**：同上 |
| 6 | 7 | 比較用（PWM 不可のはず） |

> 2 は番号を知らせる係なので候補から除外（2 自体も PWM 可）。11（PD1）は SWIO（デバッグ用）と共用で、
> 使うには `pinV32_DisconnectDebug(PD_1);` が要るため、この検証では使いません。
> 0 も PWM 可ですが、1 との取りちがえを避けるため v04 の既定の一覧からは外してあります。

### v03 INPUT_PULLUP

✅ 2026-09-01 実測

- 何もつながずに基板LEDが消えている： ✅ **はい**
  → 監視している13本すべてが `INPUT_PULLUP` で HIGH を読めている（常時LOWのピンは無し）
- GNDに触れると点灯したピン： ✅ **3・4 で確認**（教材の b2 で使う 3番を含む）
- 常に LOW を読んでしまうピン： **なし**

> **3・4 は基板に 2.2kΩ のプルアップが載っている**（I2C用）が、内蔵プルアップと
> 並列になるだけで `INPUT_PULLUP` の動作に支障はなかった。**b2 のスイッチは 3番でよい**。

### v04 analogWrite（PWM）

✅ 2026-09-01 実測

| ピン | 予想 | 結果 |
|---|---|---|
| 5 | ◎ | ✅ **ふわっと**（PWM 可） |
| 6 | ◎ | ✅ **ふわっと**（PWM 可） |
| 12 | ◎ | ✅ **ふわっと**（PWM 可） |
| 1 | ? | ❌ **まったく光らない**（`analogWrite` が無反応） |
| 10 | ? | ❌ **まったく光らない**（同上） |
| 7 | × | ✅ パッと（PWM 不可・対照実験として成立） |

- 0 … ⚠ **未検証**。公式図では PWM 可（PA1 = TIM1_CH2 の正規チャネルなので可のはず）だが、
  **e5 のモーターが「リセット後2秒だけ回って止まる」症状**が出ている（2026-09-23）。
  逆転で `analogWrite(0番)` を使っているので、ここが無反応だとその見え方になる。
  → `v13_pwm0/` で確認する
- 2 … 内蔵LEDで使用中。v05 で `analogWrite` が効いているので PWM 可

**1・10 で何も出ない理由（考察）**

`PeripheralPins.c` の `PinMap_TIM` では、1(PA2)・10(PD0) は TIM1 の **相補出力
（CH2N / CH1N）** として登録されている。相補出力はモーター駆動用の反転出力で、
アドバンストタイマの **MOE（主出力イネーブル）ビット**を立てないと端子に出ない。
コアがそこまで設定しないため、`analogWrite` を呼んでも無反応になる。
「PWM 非対応なら 127 を境に ON/OFF する」という一般則が当てはまらないケース。

**→ 教訓：ピンの可否は `PinMap_TIM` ではなく公式ピン配置図を信じること。**

### v05 analogRead

✅ 2026-09-01 実測

| ピン | 実体 | MCU | 結果 |
|---|---|---|---|
| A0 | 1 | PA2 | ✅ 追従した |
| A1 | 0 | PA1 | ✅ 追従した |
| A2 | 6 | PC4 | ✅ 追従した（教材で常用） |
| A3 | 12 | PD2 | ✅ 追従した |
| A5 | 15 | PD5 | ✅ 追従した |
| **A6** | **16** | **PD6** | ❌ **反応なし**（LEDが点灯しない＝値が 0 のまま） |

- 分解能：明暗の往復は1回だけ → **10bit（0〜1023）で正常**
- **使えるアナログ入力は A0・A1・A2・A3・A5 の5本**（A6 は使えない）

**A6 が使えない理由（コアの不具合）**

`PeripheralPins.c` の `PinMap_ADC` は ADC チャネル 6・7 を **`PA_6` / `PA_4`** として
登録しているが、**CH32V003 にそのピンは存在しない**（`variant_CH32V003F4.h` が定義して
いる PA は PA1・PA2 のみ）。ハードウェア的には ADC_IN6 = PD6、IN7 = PD4 のはずなので、
**コア側の記述ミス**と考えられる。変換表は A6 = PD6 としているため、
`analogRead(A6)` はチャネルを見つけられず 0 を返す。

- ハードの制約ではないので、**将来のパッケージ更新で直る可能性がある**
- A7（PD4）はそもそも USB の D− なので、直っても使えない
- → 教材では **A6 は使わない**。使うのは A0・A1・A2・A3・A5

### v08 tone（ブザー）✅

- 音階（ドレミファソラシド）が**上がっていく** → ✅ `tone()` 使用可・受動ブザーで正常
- `tone()` を鳴らしながら基板LED（2番）を `analogWrite` → ✅ **フェードした**
  → **TIM2 の取り合いは起きない**。音とLEDを同時に使える
- **周波数の精度： 440Hz 指定に対して実測 443.5Hz ＝ 誤差 +0.8%（14セント）**
  → 人間には聞き分けられないレベル。**b5 でメロディを鳴らしてよい**
- `tone()` はタイマー割り込みで GPIO をトグルする実装なので、**どのピンでも鳴らせる**
  → ブザーは PWM 不要の **7番**に置き、PWM 可能な 5・6・12 は LED 用に温存する

### v09 pulseIn / 超音波センサー ⚠ 重要な発見

**`micros()` は 1ms 刻みでしか進まない**（v09h で実測）。目盛り自体は正確
（1秒で100万・v09e で確認）だが、**分解能が 1ms しかない**。

その結果：

- `micros()` を使う時間計測は、すべて 1ms きざみになる
- **`pulseIn()` は使えない**。1ms 未満のパルスで 0 を返すのは上の分解能で説明がつくが、
  **50ms のパルスでも 0 を返した**（v09h ③）。`analogWriteFrequency()` 自体は
  効くことを v10a で確認しているので、**分解能とは別の不具合が pulseIn にもある**
  （ポートを直接読む `digitalPinToBitMask` / `portInputRegister` マクロが疑わしい）。
  いずれにせよ **HC-SR04 には使えない**（20cm でも反射時間は約 1.16ms）

切り分けの経過（すべて正常だったもの）:

- 5番の PWM 出力 ✅ ／ 7番の入力 `digitalRead` ✅ ／ ジャンパー ✅
- `micros()` の目盛り ✅（1秒で100万）／ `pinMode(INPUT)` の設定 ✅（ソース確認）
- → **残ったのは `micros()` の分解能だけだった**

**迂回策（v09i で実測成功）**

`delayMicroseconds()` は SysTick レジスタを直接読む**別実装**なので、
`micros()` の不具合の影響を受けない。そこで「ECHO が HIGH のあいだ、
`delayMicroseconds()` で少しずつ待ちながら回数を数える」方式にすると、
**手を近づけると明るく・遠ざけると暗く**なることを確認（2026-09-01）。

- 使うのは `digitalRead()` と `delayMicroseconds()` だけ（どちらも動作確認ずみ）
- → **e3「ものとの距離をはかろう」は成立する**。ただし教材のコードは
  `pulseIn()` を使わない形に**書きかえが必要**
**校正結果（v09j → v09k・2026-09-01）**

`delayMicroseconds(50)` にすると 1回の数えあげ ≒ 58us ＝ 音が 1cm 往復する時間になる。

| 距離 | 数えた回数 | `n - 2` | 誤差 |
|---|---|---|---|
| 10cm | 12 | 10 | 0 |
| 20cm | 22 | 20 | 0 |
| 30cm | 33 | 31 | +1 |
| 40cm | 43 | 41 | +1 |

→ **教材の式は `cm = n - 2`**（10〜40cm で誤差 ±1cm）。
   割り算も定数 58 も出てこないので、子どもに説明しやすい形になった。

### v10a analogWriteFrequency ✅

- `analogWriteFrequency(1)` ＋ `analogWrite(pin, 128)` で、テストLEDが **1秒周期で点滅**
  → ✅ **PWM の周波数を変えられる**（2026-09-01 実測）
- → **e4 サーボは 50Hz のハードウェアPWMで駆動できる**（`Servo` ライブラリ不要）
- 時間計測関数を使わない目視判定なので、`micros()` の不具合の影響を受けない確実な確認

### v10b / v10d サーボ ✅

- **`Servo` ライブラリは同梱されていない**が、**ライブラリ無しで動作確認**（2026-09-01）
- 採用した方式（v10d）：`digitalWrite` ＋ `delayMicroseconds` で
  **20msごとに 600〜2400us のパルスを送る** → 約180度の可動を実測
- ⚠ **1000〜2000us では約90度しか動かない**。これは異常ではなく、
  1.0〜2.0ms が元々のサーボ規格（中心から±45度）だから。
  最初「PWMの分解能がおかしい」と誤診したが、**v10b のハードウェアPWMも
  正しく動いていた**（205〜410 ＝ 1.0〜2.0ms ＝ 90度）
- 可動域はサーボの個体差が大きい。端でうなる場合は範囲を狭める
- → **教材にはパルス自作方式を採用**。仕組みがコードに出るため

### v06 millis / map / クロック精度

- ⚠ ボードによっては一部のピンが **USB通信や内部回路と共用**されています。
  v02・v03 で挙動がおかしいピンがあれば、そのピンを配列 `PINS[]` から外して再確認してください。
- ⚠ 出力ピンどうしを直接つながない／GNDと直結しない（LEDと抵抗を必ず入れる）。
- ⚠ ジャンパーの抜き挿しは、USBを抜いた状態で行うと安全です。
